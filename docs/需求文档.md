你是一名资深 Android 原生开发工程师。请设计并实现一个专门给老年人使用的极轻量 Android 应用。

项目暂定名：

「话费播报」

## 一、项目目标

这是一个家庭自用、侧载安装的 Android APK，不考虑 Google Play 上架。

目标用户是老人。

核心需求只有一个：

老人点击一个超大按钮，App 自动发送运营商话费查询短信；运营商回复短信后，App 自动提取话费余额，并使用 Android 系统 TTS 用中文播报结果。

整个软件必须极度轻量、简单、稳定。

设计优先级：

可靠性 > 易用性 > 低资源占用 > APK 体积 > 视觉效果

不要过度工程化。

# 三、核心工作流程

用户点击：

「查询话费」

执行：

1. 检查必要权限；
2. 获取预先配置的 SIM；
3. 使用指定 subscriptionId 对应的 SmsManager；
4. 向该运营商查询号码发送短信；
5. 手机轻微震动；
6. TTS 播报：

「正在查询话费，请稍候」

7. UI 切换为：

「正在查询……」

8. 等待运营商短信。

收到 SMS_RECEIVED_ACTION：

1. BroadcastReceiver 被系统唤醒；
2. 使用 Telephony.Sms.Intents.getMessagesFromIntent(intent)；
3. 重组 multipart SMS；
4. 获取发送者；
5. 判断是不是允许的运营商号码；
6. 解析短信；
7. 提取余额；
8. 保存最近一次余额和查询时间；
9. 通知 Activity 更新 UI；
10. 使用 TTS 播报：

「您当前的话费余额是三十六元二角」

播报结束以后不运行任何后台任务。

# 四、权限原则

只申请真正必要的权限。

优先只使用：

android.permission.SEND_SMS
android.permission.RECEIVE_SMS
android.permission.VIBRATE

不要申请 READ_SMS。

原因：

App 不需要读取短信数据库，只需要处理 SMS_RECEIVED_ACTION 中当前收到的消息。

不要申请 INTERNET。

程序第一次运行时，由家属完成权限授权。

所有权限错误必须有明确 UI 提示。

# 五、双卡支持

必须正确支持双 SIM 手机。

不要单纯依赖 SmsManager.getDefault()。

首次配置时：

使用 SubscriptionManager 获取活动 SIM。

显示：

SIM 1
SIM 2

并尽可能显示运营商名称。

家属选择：

「用这张卡查询话费」

保存其 subscriptionId 或建立可靠的重新匹配机制。

发送短信时使用指定 subscriptionId 对应的 SmsManager。

Android 12/API 31+ 优先：

SmsManager.getDefault().createForSubscriptionId(subscriptionId)

同时考虑不同 Android API 的兼容实现。

如果原 SIM 被拔出或 subscriptionId 已失效：

不要自动选择另一张 SIM 发短信。

提示：

「查询卡发生变化，请让家人重新设置」

避免误发短信。

# 七、短信安全过滤

不能解析手机收到的所有短信。

只处理：

1. 当前确实处于“等待话费查询结果”的状态；
2. SMS 到达时间与本次查询相近；
3. sender 与当前 CarrierProfile 的允许号码匹配。

例如：

发送查询后进入：

WAITING_FOR_BALANCE

设置合理超时，例如 60 秒。

只有等待期间收到的运营商短信才尝试解析。

不能因为普通银行短信中出现：

「余额」

就触发语音播报。

# 八、解析器设计

不要只写一条 Regex。

建立：

BalanceParser

以及：

ChinaMobileBalanceParser
ChinaUnicomBalanceParser
ChinaTelecomBalanceParser
FallbackBalanceParser

优先识别：

话费余额
账户余额
当前余额
可用余额
余额

金额格式可能包括：

36元
36.2元
36.20元
￥36.20
36.20 元
人民币36.20元

基础候选 Regex 可以参考：

(?:话费|账户|当前|可用)?余额\s*(?:为|[:：])?\s*(?:人民币|￥|¥)?\s*(\d+(?:\.\d{1,2})?)\s*元

但必须允许运营商专属 Parser 使用多个模式。

尤其注意避免把以下数字误认为余额：

本月消费
套餐费
流量
剩余流量
赠送金额
积分
欠费金额
充值金额

如果同一短信出现多个金额：

不要武断取第一个数字。

根据关键词上下文进行评分。

如果不能高置信度判断：

不要错误播报。

显示：

「收到运营商短信，但没有识别出话费余额」

并提供一个隐藏的调试入口，让家属查看原始短信并改进规则。
